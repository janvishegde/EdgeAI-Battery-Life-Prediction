THE FEATURE RECIPE (README section 5; board and NumPy MUST match):
 1. Frame: frame k = samples k*hop to k*hop + win - 1, whole frames only. Start with win = 30 ms, hop = 20 ms.
 2. Window: multiply by np.hanning(win).
 3. Spectrum: zero-pad to nfft (a power of 2, at least win), FFT, then P[k] = |X[k]|^2 / nfft for k = 0 ... nfft/2.
 4. Mel bands: `mels` triangles with edges evenly spaced on mel = 2595*log10(1 + f/700), from 20 Hz to fs/2.
 5. Log: 10*log10(max(band, 1e-10)).
 6. MFCC (optional): orthonormal DCT-II of the log-mel vector, keeping the first `mfcc` values.

DETAILS OF THE STARTER features.h THAT THE NUMPY VERSION MUST REPRODUCE EXACTLY (read the attached file and confirm these yourself):
 - window[n] = 0.5 - 0.5*cos(2*pi*n/(win-1))  (identical to np.hanning(win), symmetric).
 - Mel edges: edge[i] = mel2hz(m0 + (m1-m0)*i/(mels+1)) for i = 0..mels+1, m0 = hz2mel(20), m1 = hz2mel(fs/2).
 - Triangle weight for bin k at frequency f = k*fs/nfft: if lo < f <= ce, w = (f-lo)/(ce-lo); else if ce < f < hi, w = (hi-f)/(hi-ce); else 0.
   The triangles have PEAK 1 (they are not area-normalised). Note the strict/non-strict inequality at the edges.
 - band[m] = sum over k of w[m][k]*P[k], then 10*log10(max(band, 1e-10)).
 - MFCC DCT: row 0 scaled sqrt(1/mels), other rows sqrt(2/mels), cos(pi*q*(2m+1)/(2*mels)).
 - The board dequantises int16 samples as x = q * (1/32767) * scale and works in float32.
 - IMPORTANT: compare the board with NumPy run on the SAME QUANTISED samples, i.e. quantise -> pack -> unpack (quant.py) -> float32,
   not on the original float clips. (Comparing with the original float clips is Mission 5's job, not Mission 3's.)

HOW THE BOARD LINK WORKS (read board_link.py and the .ino; here is the summary):
 - from board_link import Board;  b = Board("<port>", baud=921600);  r = b.stream(payload, fs=16000, fmt="i16", scale=1.0,
   win=480, hop=320, nfft=512, mels=40, mfcc=0, feat=True, store="none", speed=1.0, samples_per_packet=320)
 - r["features"] is (frames x outputs) computed ON THE BOARD; r["first_sample"] is each frame's first sample index; r["compute_us"] is the
   board time per frame in microseconds; r["lag_s"] is how late each frame arrived after its last sample was due (only when speed > 0);
   r["expected_features"], r["lost_features"], r["bad_crc_back"], and r["board"] (the board's own summary: frames_ok, bad_crc,
   seq_gaps, features, max_us, avg_us, uart_errors, ms ...).
 - speed=1.0 is real time, 4.0 is four times faster, 0 is as fast as the link allows. feat=False means the board only receives.
 - Our scripts m1_pipe.py and m2_storage.py show how we connect (the `connect()` function in m1_pipe.py finds the board's baud rate).
   New scripts for Mission 3 must be written in new files (suggested names: m3_features.py, m3_compare.py, m3_speed.py).

THE STARTER'S SLOW PART (from features.h; verify by reading it): compute() calls dft(), a textbook DFT. For each of the nb = nfft/2+1 = 257
output bins it loops over all win = 480 samples and calls cosf() and sinf() for every sample: 257 * 480 = 123,360 loop iterations,
i.e. 246,720 trig calls PER FRAME. Then the mel stage does 40 * 257 = 10,280 multiply-adds and 40 log10f calls. At win 480 / hop 320 /
16 kHz a new frame is needed every 20 ms, so the whole compute() must finish well under 20,000 microseconds, or the board falls behind
(lag_s grows). A radix-2 FFT of 512 points needs only 9 stages * 256 = 2,304 butterflies plus a one-time twiddle table.
Teach these ideas (twiddle table computed ONCE in begin(), bit-reversal, in-place butterflies, why N must be a power of 2), but have me
write the code with you. ESP-DSP is allowed only if I can explain what it does; the plain C++ radix-2 FFT is the recommended route.
Hints for the later accuracy check: the 0.05 dB tolerance applies to EVERY output value including quiet bands; use float32 carefully,
and compute the twiddle factors in double precision once, then store them as float.
